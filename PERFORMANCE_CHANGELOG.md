## 2026-07-21 — Пакет 2: gzip для production-статики Nginx

### Найденная проблема

Nginx 1.24.0 напрямую отдавал `/assets/`. В глобальной конфигурации было включено `gzip on`, но `gzip_types` оставался закомментирован. Поэтому CSS и JavaScript отвечали без `Content-Encoding` и передавались целиком.

Контрольные ответы до изменения:

- `home-stability-hotfix.css`: 196 331 байт;
- `app.min.js`: 310 426 байт;
- заголовки `Content-Encoding` и `Vary` отсутствовали.

### Что изменено

Только на production-сервере, внутри `location ^~ /assets/` виртуального хоста `gptishka.shop`, добавлено:

```nginx
# GPTishka static compression
gzip_vary on;
gzip_min_length 1024;
gzip_comp_level 5;
gzip_types text/plain text/css application/javascript application/json application/xml image/svg+xml;
```

Глобальный `/etc/nginx/nginx.conf`, HTML, API, admin-домен, cache headers и код сайта не менялись.

### Резервная копия и откат

Перед записью создана копия:

`/etc/nginx/sites-available/gptishka.shop.pre-gzip-20260721T123947Z`

Команда ручного отката с обязательной проверкой:

```bash
cp -a /etc/nginx/sites-available/gptishka.shop.pre-gzip-20260721T123947Z /etc/nginx/sites-available/gptishka.shop
nginx -t && systemctl reload nginx
```

### Почему это безопасно

- Настройка ограничена статическим `/assets/` основного домена.
- Сжимаются только текстовые MIME-типы размером от 1 КиБ.
- PNG и другие уже сжатые изображения не включены в `gzip_types`.
- До reload выполнен успешный `nginx -t`.
- После reload Nginx имеет статус `active`; повторный `nginx -t` успешен.
- Распакованные gzip-ответы CSS и JS побайтово совпадают с ответами `identity` по SHA-256.

### Полученный эффект

Контрольные production-файлы:
