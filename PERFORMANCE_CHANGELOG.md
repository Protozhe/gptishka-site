# PERFORMANCE_CHANGELOG

## 2026-07-21 — Пакет 2: gzip для production-статики Nginx

### Найденная проблема

Nginx 1.24.0 напрямую отдавал `/assets/`. В глобальной конфигурации было включено `gzip on`, но `gzip_types` оставался закомментирован. Поэтому CSS и JavaScript отвечали без `Content-Encoding` и передавались целиком.

Контрольные ответы до изменения:

- `home-stability-hotfix.css`: 196 331 байт;
- `app.min.js`: 310 426 байт;
- заголовки `Content-Encoding` и `Vary` отсутствовали.

### Что изменено

Только на production-сервере, внутри `location ^~ /assets/` виртуального хоста `gptishka.shop`, добавлено:

```nginx
# GPTishka static compression
gzip_vary on;
gzip_min_length 1024;
gzip_comp_level 5;
gzip_types text/plain text/css application/javascript application/json application/xml image/svg+xml;
```

Глобальный `/etc/nginx/nginx.conf`, HTML, API, admin-домен, cache headers и код сайта не менялись.

### Резервная копия и откат

Перед записью создана копия:

`/etc/nginx/sites-available/gptishka.shop.pre-gzip-20260721T123947Z`

Команда ручного отката с обязательной проверкой:

```bash
cp -a /etc/nginx/sites-available/gptishka.shop.pre-gzip-20260721T123947Z /etc/nginx/sites-available/gptishka.shop
nginx -t && systemctl reload nginx
```

### Почему это безопасно

- Настройка ограничена статическим `/assets/` основного домена.
- Сжимаются только текстовые MIME-типы размером от 1 КиБ.
- PNG и другие уже сжатые изображения не включены в `gzip_types`.
- До reload выполнен успешный `nginx -t`.
- После reload Nginx имеет статус `active`; повторный `nginx -t` успешен.
- Распакованные gzip-ответы CSS и JS побайтово совпадают с ответами `identity` по SHA-256.

### Полученный эффект

Контрольные production-файлы:

| Ресурс | До | После | Экономия |
| --- | ---: | ---: | ---: |
| `home-stability-hotfix.css` | 196 331 | 23 230 | −173 101 байт (−88,2%) |
| `app.min.js` | 310 426 | 65 182 | −245 244 байта (−79,0%) |

Для обоих ответов присутствуют `Content-Encoding: gzip` и `Vary: Accept-Encoding`. Контрольный PNG остаётся несжатым: 2 055 197 байт до и после.

Медиана трёх production Lighthouse mobile-запусков:

| Метрика | До | После | Изменение |
| --- | ---: | ---: | ---: |
| Общий transfer | 16 208 834 байта | 15 412 774 байта | −796 060 байт |
| CSS + JavaScript transfer | 1 018 440 байт | 299 887 байт | −718 553 байта (−70,6%) |
| FCP | 6 774 мс | 2 909 мс | −3 865 мс |
| LCP | 53 677 мс | 47 365 мс | −6 312 мс |
| TBT | 186 мс | 51 мс | −135 мс |

LCP остаётся сильно нестабильным из-за тяжёлого динамического hero; наиболее надёжный эффект пакета — сокращение CSS/JS transfer на 718 553 байта.

### Выполненные проверки

- `nginx -t` до и после reload — успешно.
- `systemctl is-active nginx` — `active`.
- В journal Nginx за 10 минут после изменения ошибок нет.
- `/`, `/en/`, `/catalog/`, `/chatgpt` и `/api/public/products` — HTTP 200.
- Проверены production-главная, hero-слайдер, FAQ, страница ChatGPT, открытие и закрытие формы заказа.
- Реальная оплата и отправка заказа не выполнялись.

### Ошибки и ограничения проверок

- Lighthouse на Windows сохраняет корректный JSON и затем возвращает `EPERM` при удалении временного Chrome-профиля. Все три отчёта созданы и обработаны.
- Локальный пакет устранения дубля `chatgpt-card.png` ещё не развёрнут на production и не входит в эти live-метрики.
- Коммит локальных документов не создан: отсутствуют Git `user.name` и `user.email`.

### Следующий рекомендуемый этап

Оптимизировать самые тяжёлые PNG с сохранением исходников как fallback и обязательным visual diff. Серверную конфигурацию в этот пакет больше не менять.

## 2026-07-21 — Пакет 1: устранение двойной загрузки ChatGPT-изображения

### Найденная проблема

Главная и другие storefront-страницы использовали один файл `assets/img/services/chatgpt-card.png` по двум URL: с `?v=20260622-header1` в header и без query-параметра в runtime-коде и карточках. Lighthouse загружал оба ответа по 2 055 874 байта.

### Что изменено

- Все активные runtime, каталоговые и gallery-ссылки приведены к существующему cache-busting URL `/assets/img/services/chatgpt-card.png?v=20260622-header1`.
- Обновлено соответствующее ожидание существующей проверки `scripts/check-chatgpt-video-bg.js`.
- Содержимое PNG, HTML-структура, CSS, тексты, API и бизнес-логика не менялись.

### Изменённые файлы

- `assets/js/app.js`
- `assets/js/app.min.js`
- `main.js`
- `catalog/index.html`
- `catalog/ai/index.html`
- `en/catalog/index.html`
- `en/catalog/ai/index.html`
- `chatgpt.html`
- `en/chatgpt.html`
- `scripts/check-chatgpt-video-bg.js`
- `PERFORMANCE_CHANGELOG.md`
- `visual-baseline/after/dedupe-chatgpt-card/` — 12 контрольных снимков

### Почему это безопасно

Оба прежних URL отдавали один физический PNG. Выбран уже использовавшийся версионированный URL, поэтому сохраняется cache busting и исключается риск получения старого изображения из долгого кеша. Меняется только ключ сетевого кеша, а не визуальный ресурс.

### Полученный эффект

Медиана трёх локальных Lighthouse mobile-запусков:

| Метрика | До | После | Изменение |
| --- | ---: | ---: | ---: |
| Запросы `chatgpt-card.png` | 2 | 1 | −1 |
| Transfer этого PNG | 4 111 748 байт | 2 055 874 байта | −2 055 874 байта |
| Общий transfer | 11 949 310 байт | 9 893 514 байт | −2 055 796 байт (−17,2%) |
| Lighthouse Performance mobile | 57 | 73 | +16 пунктов |

Рост Lighthouse-score является лабораторным результатом и может колебаться из-за динамического hero. Надёжный эффект пакета — удаление одного сетевого ответа и около 1,96 МиБ передачи.

Размер PNG и production-файлов практически не изменился: оптимизация уменьшает сетевой дубль, а не файл на диске.

### Выполненные проверки

- `node --check`: `server.js`, `main.js`, `assets/js/app.js`, `assets/js/app.min.js` — успешно.
- Три синхронные копии storefront-скрипта имеют одинаковый SHA-256.
- Активных ссылок `chatgpt-card.png` без версии в HTML/JS не осталось.
- `/`, `/en/`, `/catalog/`, `/catalog/ai/`, `/chatgpt`, `/en/chatgpt` и версионированный PNG — HTTP 200.
- Проверены hero-слайдер, FAQ, каталог, переход в ChatGPT, открытие и закрытие формы заказа; заказ не отправлялся.
- Созданы 12 after-снимков в тех же viewport. Три снимка совпали с baseline побайтово; остальные просмотрены вручную. Отличия относятся к динамическому hero, кадру видео и support widget; новых изменений layout или оформления не обнаружено.

### Ошибки и ограничения проверок

- `scripts/check-chatgpt-video-bg.js` доходит до существующей проверки CSS и падает на отсутствующем ожидаемом hero stacking pattern. Эта ошибка не связана с URL изображения и в этом пакете не исправлялась.
- Lighthouse на Windows сохраняет корректный JSON, после чего завершает процесс с `EPERM` при очистке временного профиля Chrome. Все три отчёта были созданы и разобраны.
- Коммит не создан: в репозитории по-прежнему не настроены `user.name` и `user.email`.

### Оставшиеся риски

- Production-показатели появятся только после отдельного деплоя; на сервер изменения не отправлялись.
- Динамические кадры требуют ручного контроля поверх pixel diff.

### Рекомендация для следующего этапа

Отдельно включить gzip для статических CSS/JS в проверенной Nginx-конфигурации с `nginx -t` и возможностью мгновенного отката. Это серверное изменение не входит в текущий пакет.
