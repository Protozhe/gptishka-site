Дата исходного baseline: 2026-07-21

Исходный production commit: `c1f5a7b3642a970bfe4b5691489a12d42276c242`
Локальный адрес: `http://127.0.0.1:4170/`

Эта инструкция фиксирует внешний вид до оптимизации. Файлы baseline находятся в `visual-baseline/before/` и не подключаются к production-страницам.

## Размеры экрана

Основные страницы проверяются минимум в трёх viewport:

| Имя | Размер |
| --- | ---: |
| Mobile | 375 × 812 |
| Tablet | 768 × 1024 |
| Desktop | 1440 × 900 |

Масштаб браузера должен быть 100%, device pixel ratio — без ручного переопределения. Перед снимком нужно дождаться шрифтов, API-данных и изображений. Для тяжёлого hero-баннера требуется дополнительная стабилизация: ранний desktop-снимок может получить пустой фон.

## Известное исходное состояние

- На главной `#langSwitch` получает класс `open`, но dropdown остаётся `display: none` из-за текущего CSS. Файл `state-language-open.jpg` фиксирует именно это исходное поведение. Не считать его результатом оптимизации.
- Скрипт ищет `[data-home-menu-toggle]`, однако такого элемента нет в текущем DOM главной. Поэтому отдельный baseline открытого мобильного меню создать невозможно.
- Локально `admin-api.gptishka.shop` не разрешается через DNS. Встроенные fallback-данные позволяют отобразить основные страницы, но `/api/public/homepage-content` возвращает `502`.
- Отдельные стабильные визуальные экраны loading/error в текущем интерфейсе не обнаружены. Их нужно проверять через безопасный mock или перехват API, когда такой тестовый механизм будет добавлен вне production-бандла.
- Контент hero-слайдера и данные каталога динамические. Перед сравнением нужно выбрать тот же слайд и дождаться одинакового состояния данных.
- На исходных снимках видны уже существующие проблемы отдельных изображений и мобильного переполнения. Они считаются baseline до отдельного согласованного исправления.

## Порядок сравнения после изменения

1. Запустить локальную production-версию с теми же переменными окружения и без изменения данных.
2. Создать каталог `visual-baseline/after/<имя-этапа>/`.
3. Снять те же URL, viewport и интерактивные состояния с теми же именами файлов.
4. Сначала сравнить изображения попарно на 100% масштабе и наложением с прозрачностью около 50%.
5. Для автоматического pixel diff маскировать только реально динамические счётчики/временные данные. Нельзя маскировать карточки, CTA, изображения, текст или layout.
6. Любой diff дополнительно проверить вручную в браузере: автоматический diff чувствителен к сглаживанию шрифтов и кадрам анимации.
7. Проверить консоль, сетевые ошибки и пользовательские сценарии. Визуальное совпадение само по себе недостаточно.

## Недопустимые отличия

- изменение ширины, высоты, позиции, отступов или порядка блоков;
- перенос текста, которого нет в baseline при том же viewport и шрифте;
- изменение шрифта, начертания, размера, цвета, прозрачности или межстрочного интервала;
- изменение crop, масштаба, прозрачности или качества изображения;
- исчезновение контента, CTA, навигации, юридического уведомления или support widget;
- изменение radii, теней, границ, фона, blur и состояния hover/focus;
- изменение скорости, направления и последовательности анимаций;
- layout shift после загрузки изображения, шрифта, API или открытия модального окна;
- другое состояние тарифа, формы или способа оплаты при одинаковых действиях;
- новая ошибка в консоли или новый неуспешный сетевой запрос.

Допустимы только различия, прямо ожидаемые от конкретной задачи и не меняющие вид: например, другой URL ресурса при побайтово/визуально идентичном изображении или уменьшенный размер сетевой передачи.

## Минимальный функциональный прогон

После каждого пакета изменений проверить:

1. Главная и первый экран.
2. Переключение hero-слайдов.
3. Каталог и открытие карточки продукта.
4. Выбор тарифа.
5. Открытие формы заказа и переключение оплаты без отправки.
6. Закрытие модального окна.
7. FAQ.
8. Русскую и английскую версии.
9. Видео.
10. Telegram/VK-ссылки.
11. Ошибку API и повторную загрузку с холодным/тёплым кешем.

Если визуальный diff не объясняется задачей, изменение нельзя принимать до выяснения причины.
