# Homepage promo slider design

## Цель

Заменить trust-бейджи и правый блок “Как проходит подключение” на главной странице GPTishka одним большим промо-баннером/слайдером, который можно полностью редактировать из админки.

## Что должно получиться

- На главной странице появляется крупный premium-слайдер под hero CTA.
- Слайдер показывает новости, акции и важные предложения: ChatGPT Go без входа, V*N-ключ после оплаты, Claude / Grok доступны.
- Слайды можно добавлять, отключать, удалять, сортировать и редактировать в админке.
- Для каждого слайда задаются: бейдж, заголовок, текст, текст кнопки, ссылка кнопки, фон-картинка, цвета/градиент и активность.
- Если API недоступно или слайдов нет, главная показывает безопасные fallback-слайды из HTML/JS и не ломает первый экран.
- Изменения не затрагивают товары, checkout, оплату, модальные окна и логику заказов.

## Архитектура

Отдельная сущность `HomepageBannerSlide` хранится в admin backend через Prisma. Это не часть товарной витрины, потому что баннеры — редакционный контент главной, а не карточки товаров.

Backend добавляет admin API для CRUD и загрузки фоновой картинки, а public API отдаёт только активные слайды. Storefront на главной получает слайды через public API, рендерит их поверх fallback-разметки и управляет плавной сменой.

## Компоненты

- `apps/admin-backend/prisma/schema.prisma` — модель `HomepageBannerSlide`.
- `apps/admin-backend/src/modules/homepage/` — admin/public routes, service, DTO validation.
- `apps/admin-backend/src/modules/files/files.service.ts` — загрузка изображений баннеров в `/uploads/homepage-banners/`.
- `apps/admin-ui/src/pages/HomepageBannersPage.tsx` — редактор слайдов в админке.
- `apps/admin-ui/src/layout/AdminLayout.tsx` и `apps/admin-ui/src/main.tsx` — новый пункт “Главная”.
- `index.html` — замена trust/process блоков на промо-слайдер.
- `assets/css/home-wide-marketplace.css` — визуал слайдера.
- `assets/js/home-promo-slider.js` — загрузка/рендер/автопереключение слайдов.
- `scripts/verify-homepage-wide-layout.mjs` — статическая проверка новой структуры.

## Поведение

Public API возвращает активные слайды, отсортированные по `sortOrder`, затем по дате создания. Storefront использует API-слайды, если они есть; иначе оставляет встроенные fallback-слайды.

Слайдер:
- автоматически переключается;
- имеет точки навигации;
- не блокирует кнопки и ссылки;
- соблюдает `prefers-reduced-motion`;
- на mobile остаётся читаемым и не создаёт горизонтальный scroll.

## Ошибки и fallback

- Ошибка загрузки API не должна показываться клиенту.
- Если у слайда нет картинки, используется градиент.
- Удаление картинки удаляет файл, если он находится в разрешённой папке загрузок.
- Public API не отдаёт отключённые слайды.
